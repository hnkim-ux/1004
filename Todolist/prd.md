# PRD: 오늘의 할일 (Today's To-Do) 웹페이지

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.1 (설계 단계) |
| 작성일 | 2026-11-02 |
| 상태 | 초안 — 구현 전 |

---

## 1. 개요

### 1.1 배경
하루 단위로 해야 할 일을 빠르게 적고, 완료 여부를 체크하며, 하루를 마무리할 때 진행 상황을 한눈에 볼 수 있는 가벼운 웹페이지가 필요하다. 복잡한 프로젝트 관리 도구가 아니라 "오늘"에 집중하는 단순한 도구를 목표로 한다.

### 1.2 목표
- 3초 안에 할일 하나를 추가할 수 있다.
- 오늘 할일의 진행률을 한눈에 확인할 수 있다.
- 별도 설치·로그인 없이 브라우저에서 바로 사용하며, 새로고침해도 데이터가 유지된다.

### 1.3 비목표 (Out of Scope, v1)
- 회원가입/로그인, 다중 사용자, 기기 간 동기화
- 서버/백엔드 및 데이터베이스
- 반복 일정, 알림(푸시), 캘린더 연동
- 협업(공유, 담당자 지정)

---

## 2. 대상 사용자 및 시나리오

### 2.1 페르소나
- **직장인/학생**: 아침에 오늘 할 일 3~10개를 적고, 하루 동안 하나씩 체크한다.

### 2.2 사용자 시나리오
1. 아침에 페이지를 열면 오늘 날짜와 빈(또는 이월된) 목록이 보인다.
2. 입력창에 할일을 입력하고 Enter로 추가한다.
3. 일을 마치면 체크박스를 눌러 완료 처리한다. 진행률 바가 갱신된다.
4. 잘못 적은 항목은 더블클릭해 수정하거나 삭제한다.
5. 다음 날 페이지를 열면, 어제 끝내지 못한 항목을 오늘로 가져올지 선택할 수 있다.

## 6. 데이터 설계

### 6.1 Todo 모델
```ts
interface Todo {
  id: string;          // crypto.randomUUID()
  text: string;        // 1~200자, 앞뒤 공백 제거
  done: boolean;
  important: boolean;  // F-05
  date: string;        // 소속 날짜 "YYYY-MM-DD" (로컬 시간)
  createdAt: number;   // epoch ms
  completedAt?: number;
  order: number;       // 정렬용
}
```

### 6.2 저장 구조 (localStorage)
| 키 | 값 |
|---|---|
| `todolist:v1:todos` | `Todo[]` JSON |
| `todolist:v1:lastOpenedDate` | `"YYYY-MM-DD"` — 이월 배너 표시 판단용 |
| `todolist:v1:filter` | `"all" \| "active" \| "done"` |

- 키에 버전(`v1`)을 포함해 향후 스키마 변경 시 마이그레이션 가능하도록 한다.
- 파싱 실패 시 빈 목록으로 시작하고 원본은 `todolist:v1:todos:backup`에 보존.

### 6.3 정렬 규칙
1. `important = true` 우선
2. 같은 그룹 내에서는 `order` 오름차순
3. 완료 여부로는 재정렬하지 않음 (체크 시 위치가 튀지 않도록)

## 7. 기술 설계

### 7.1 기술 스택 (제안)
- **HTML + CSS + Vanilla JavaScript** — 빌드 도구 없이 `index.html`을 바로 열어 실행.
  - ES Modules는 `file://`에서 CORS로 막히므로, 순서대로 로드하는 일반 스크립트 + `window.TD` 네임스페이스로 모듈을 나눈다.
- 선택 근거: 기능 규모가 작고, 백엔드가 없으며, 의존성 없이 배포(정적 호스팅)가 가능.
- 확장 시 대안: React + Vite (P2 기능이 늘어날 경우 재검토).

### 7.2 폴더 구조 (예정)
```
todolist/
├── prd.md          # 본 문서
├── index.html      # 마크업
├── styles.css      # 스타일, 라이트/다크 토큰
└── js/
    ├── app.js      # 진입점, 이벤트 바인딩
    ├── store.js    # 상태 관리 + localStorage 입출력
    ├── render.js   # DOM 렌더링
    └── date.js     # 로컬 날짜 유틸 (YYYY-MM-DD, 표시 포맷)
```

### 7.3 상태 흐름
```
사용자 입력 → app.js(이벤트) → store.js(상태 변경 → localStorage 저장)
          → render.js(상태 기반 전체/부분 렌더링)
```
- 단방향 흐름: 상태 변경은 `store`의 함수(`add`, `toggle`, `update`, `remove`, `clearDone`, `carryOver`)로만 수행.
- 다른 탭에서의 변경은 `storage` 이벤트로 감지해 재렌더링 (P1).

### 7.4 날짜 처리 주의사항
- `toISOString()`은 UTC 기준이므로 사용하지 않고, 로컬 연·월·일로 `YYYY-MM-DD` 생성.
- 페이지를 자정 넘어 열어둔 경우: 포커스/가시성 변경 시 날짜를 재확인해 "오늘"을 갱신.

## 8. 수용 기준 (Acceptance Criteria)

- [ ] 할일을 입력하고 Enter를 누르면 목록에 추가되고 입력창이 비워진다.
- [ ] 공백만 입력하면 추가되지 않는다.
- [ ] 체크 시 취소선이 표시되고 진행률이 즉시 갱신된다.
- [ ] 더블클릭으로 수정, Enter 저장 / Esc 취소가 동작한다.
- [ ] 삭제 후 새로고침해도 삭제 상태가 유지된다.
- [ ] 새로고침 후 모든 데이터와 선택한 필터가 유지된다.
- [ ] 날짜가 바뀐 뒤 접속하면 미완료 항목 이월 배너가 표시된다.
- [ ] 마우스 없이 Tab/Enter/Space만으로 추가·완료·삭제가 가능하다.
- [ ] 360px 폭에서 가로 스크롤 없이 사용 가능하다.
- [ ] 다크 모드에서 텍스트 대비가 충분하다.

## 11. 데스크톱 위젯 (Windows)

웹페이지를 그대로 감싼 Electron 앱. 소스는 `widget/`.

| 항목 | 내용 |
|---|---|
| 창 | 테두리 없는 380×640 창, 처음 실행 시 주 모니터 오른쪽 위. 위치·크기 기억. 작업 표시줄에는 표시하지 않음 |
| 상단 바 | 끌어서 이동, 📌 항상 위에 표시 토글, ✕ 트레이로 숨기기 |
| 트레이 | 클릭으로 보이기/숨기기. 메뉴: 항상 위에 표시, Windows 시작 시 실행, 종료 |
| 페이지 | 루트의 `build.mjs`로 만든 단일 파일을 `widget/page/index.html`로 복사해 사용 (웹과 동일 코드) |
| 저장 | 앱 전용 localStorage. 크롬에서 연 페이지와는 데이터가 분리됨 |
| 명령 | `npm start` 개발 실행, `npm run dist` 설치 파일 빌드 → `widget/release/` |
